# Internacionalização (en / pt-BR)

Idiomas suportados: **`en`** (fallback) e **`pt-BR`**.

Voltar para o [índice transversal](README.md).

---

## O princípio

**O backend não traduz. O backend identifica.**

Um erro, uma notificação ou um status que sai do backend carrega três coisas:

```jsonc
{
  "code": "WORKSPACE_NOT_ALLOWED",              // estável, para lógica
  "messageKey": "session.error.workspaceNotAllowed", // para tradução no cliente
  "params": { "path": "/etc" }                  // interpolação
}
```

Quem transforma isso em *"O diretório /etc não está liberado"* é o web ou o Flutter, no
idioma daquele usuário.

**Por quê:** o mesmo backend serve um navegador em pt-BR e um celular em en ao mesmo tempo.
Traduzir no servidor obrigaria a negociar idioma em toda requisição e ainda deixaria o texto
fora do controle do designer da UI.

### A única exceção

**Push notification.** O payload vai pronto para o SO do aparelho, que não sabe traduzir. Aí
o backend traduz — usando o idioma que o `Device` registrou no cadastro. O catálogo do
backend existe **só para isso**. Ver [backend/03-modules.md](../backend/03-modules.md).

## Chaves

Formato: `<domínio>.<contexto>.<identificador>`, em `lowerCamelCase` no último segmento.

```
session.error.workspaceNotAllowed
session.action.interrupt
permission.prompt.title
permission.prompt.allowOnce
workspace.empty.description
common.action.cancel
common.error.unexpected
```

Regras:

- **Nunca** aninhe além de três segmentos.
- `common.*` é só para o que aparece em três telas ou mais. Na dúvida, duplique — chave
  compartilhada prematuramente vira chave que ninguém pode mudar.
- Chave é **inglês**, sempre. Ver [01-language-and-naming.md](01-language-and-naming.md).
- Chave órfã (sem uso) e chave faltando em um idioma **quebram o build**. Ver "Garantias".

### Interpolação e plural

Use interpolação nomeada, nunca posicional — a ordem das palavras muda entre idiomas.

```jsonc
// ✅
"session.tool.running": "Running {toolName}…"
// ❌ — impossível traduzir para uma língua com ordem diferente
"session.tool.running": "Running {0}…"
```

Plural usa a sintaxe ICU nas três pontas:

```
"session.turn.count": "{count, plural, =0 {No turns} one {# turn} other {# turns}}"
```

## Implementação por ponta

| Ponta | Biblioteca | Formato | Local dos catálogos |
|---|---|---|---|
| Web | `react-i18next` | JSON | `web/src/shared/i18n/locales/{en,pt-BR}.json` |
| Mobile | `flutter_localizations` + `intl` | ARB | `mobile/lib/l10n/app_{en,pt}.arb` |
| Backend | `i18next` (só push) | JSON | `backend/src/shared/i18n/locales/{en,pt-BR}.json` |

**Por quê ARB no Flutter:** é o formato oficial do time do Flutter, com geração de código
type-safe (`AppLocalizations.of(context).sessionErrorWorkspaceNotAllowed`). Chave inexistente
vira erro de compilação, não string crua na tela.

### Negociação de idioma

| Canal | Como |
|---|---|
| HTTP | header `Accept-Language` |
| WebSocket | campo `locale` no handshake; pode ser trocado com o comando `session.setLocale` |
| Push | `Device.locale`, gravado no registro do aparelho |

Fallback: idioma pedido → `en` → a própria chave (nunca string vazia, nunca `null`).

## Garantias automatizadas

Estas checagens rodam no CI e **quebram o build**:

1. **Paridade de chaves** — toda chave existe em `en` e em `pt-BR`. Faltar em um é erro.
2. **Sem órfãs** — chave declarada e nunca usada é erro (vira lixo que ninguém remove).
3. **Sem literal na UI** — regra de lint proibindo JSX text node e `Text('...')` com string
   literal apresentável. Ver os documentos de teste de cada ponta.
4. **Params casam** — se `en` usa `{path}`, `pt-BR` também precisa usar `{path}`.

## Regras de escrita

- Escreva primeiro em **`en`**, depois traduza. O inglês é a fonte de verdade.
- Não concatene fragmentos traduzidos. Uma frase = uma chave.
  ```
  // ❌ t('common.the') + ' ' + t('session.word') + ' ' + t('common.failed')
  // ✅ t('session.error.failed')
  ```
- Não coloque markup dentro do valor. Use `<Trans>` (web) ou `RichText` (Flutter).
- Data, hora, número e moeda **não** vão no catálogo — use o formatador de locale
  (`Intl.DateTimeFormat`, `DateFormat`). Fuso é sempre resolvido no cliente; o backend
  transmite ISO-8601 em UTC.
